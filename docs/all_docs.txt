南大EL程序设计大赛用户分析与同类产品分析报告
一、分析背景与目标
1.1 分析背景
当前新工科、新文科、交叉学科快速发展，市场对复合型人才需求持续扩张，南京大学大力推进跨学科、辅修培养制度，开设完整辅修专业体系。根据南大官方公开数据，全校本科在校生共15343人，校内开设本科课程3267门，选修课占比36.88%，具备充足跨专业学习基础；每年均有大量学生申请转专业，如2022年大一、大二分别有165人、57人获得转专业资格，电子信息、计算机、法学等复合热门方向申请人数最多，足以证明本科生跨专业、复合发展需求旺盛。
但通过小红书、微信平台学生真实分享、校内舆情调研发现：南大现行辅修制度存在学分高门槛、多校区通勤、课程冲突、信息分散等特有问题，学生在辅修决策、课程规划、跨学科自学、复合就业规划全流程存在大量共性痛点。现有通用学习工具、校园平台仅能单一查询政策，无法提供一站式个性化跨学科成长指导，因此本团队开发面向南大学生的复合型人才智能体，精准解决学生跨专业学习全流程难题。
1.2 分析目标
量化南大本科生潜在辅修、跨专业学习人群基数，明确目标用户规模；
归纳学生跨学科学习全流程高频痛点，为智能体四大核心功能（辅修推荐、课程规划、职业发掘、自学助手）提供需求依据；
划分不同需求类型学生用户分层，匹配差异化智能体交互逻辑；
调研同类型校园/跨学科智能体，挖掘本项目差异化创新亮点。
二、数据来源与样本说明 
2.1 定量数据来源 
1. 南京大学信息公开网2023-2024学年官方办学数据：全校本科生总人数、课程开设总量、选修课占比，用于测算潜在需求人群规模； 
2. 南大官方转专业公示数据：大一、大二转专业录取人数、热门转入专业分布，佐证学生跨专业学习客观需求；
3. 网络舆情定量统计：小红书、微信平台检索近3年南大学生辅修相关分享帖，统计各类痛点出现频次，量化学生问题集中程度。
2.2 定性数据来源
小红书平台南大辅修、跨专业学习分享帖、评论区文本，整理学生真实踩坑经历； 
2. 微信公众号、校友吐槽推文，获取南大独有的辅修高学分、跨校区通勤等专属痛点；
跨专业、跨考经验分享内容，挖掘零基础跨学科学习、复合就业规划深层焦虑； 
4. 南大官方辅修培养方案、选课规则、转专业政策文件，作为需求分析客观背景支撑。
2.3 样本说明 
本次分析覆盖南京大学全体15343名本科生作为整体目标人群；舆情文本样本覆盖2023-2025年小红书、微信全部高互动南大辅修相关帖子，覆盖文、理、工、商、医全部院系学生分享内容，样本覆盖全部主流复合学习赛道（文转码、生物+金融、经管辅修法学等），数据具备校园全域代表性。
三、用户整体概况分析 
3.1 基础人群规模概况 
1. 整体基数：南大全日制本科生15343人，是本智能体全部目标用户；
2. 需求佐证：每年超200名学生成功转专业，电子信息、软件工程、计算机、法学等复合热门方向申请热度最高，大量未转专业学生选择辅修作为跨学科路径；
3. 学习供给基础：全校3267门本科课程中选修课占比36.88%，学校具备完整辅修培养方案、多专业辅修通道，客观支撑学生复合发展需求。 
3.2 用户行为整体特征 
1. 需求周期集中：大二、大三为主力需求人群，该阶段主修课业压力最大，同时面临科研、实习、考研、出国规划，叠加辅修学习，矛盾最为突出； 
2. 信息获取渠道单一：学生依赖小红书、社群、学长学姐经验获取辅修信息，官方政策文件晦涩、分散，极少主动查阅本科生院完整培养方案； 
3. 行为痛点共性极强：课程冲突、跨校区通勤、无法评估辅修难度、缺少体系化自学资源、复合就业信息零散是重复出现最高的行为阻碍； 
4. 人群分化：一部分学生希望走官方辅修体系获取证书，另一部分学生仅需要跨专业自学资源，无拿证需求，两类人群需求存在明显区分。 
3.3 用户需求分层大盘 
1. 强需求人群：有明确辅修计划/转专业意向，主动搜集政策、课程、就业信息； 
2. 观望人群：有复合发展想法，但因门槛、时间、难度问题犹豫，无法做出决策； 
3. 弱需求人群：仅需要零散跨专业自学资源，不参与校内官方辅修； 
4. 无需求人群：仅专注本专业，无跨学科学习规划。 

四、用户分层与画像构建 
4.1 核心高价值用户：有明确辅修计划的大二/大三本科生
用户标签：20-23岁、主修课业压力大、目标获取辅修证书、有明确复合就业/升学规划、高频查询政策与课表 
1. 基础信息：大二、大三为主，覆盖商科、生命科学、中文、计算机等复合热门专业，是转专业落选后选择辅修的主力人群； 
2. 行为特征：反复查阅辅修学分要求、开课时间，手动对比主修与辅修课表，主动询问学长辅修难度、保研/出国含金量； 
3. 心理特征：愿意投入大量时间完成50学分辅修，重视证书对求职、留学的加成，极度在意时间成本、课程冲突、跨校区通勤损耗； 
4. 核心痛点： 
- 南大辅修50学分门槛远高于其他高校，课业负荷过重； 
- 辅修课程集中鼓楼校区，仙林主修生通勤单程40-60分钟，时间损耗巨大； 
- 手动排课无法规避主修、辅修时间冲突，抢课名额少； 
- 无法提前评估零基础跨专业辅修的学习难度； 
5. 匹配智能体功能：辅修智能推荐、个性化课程规划助手（核心亮点功能）。 
典型用户故事：21岁生科院大三本科生，计划辅修金融走生物医药行研赛道，多次在小红书发帖吐槽主修实验课与金融辅修课完全撞时间，跨校区通勤占用大量实习准备时间，不清楚自身基础能否跟上金融课程，希望工具自动生成无冲突四年课表并评估辅修难度。 

4.2 普通价值用户：观望型跨专业意向学生
用户标签：19-22岁、大一/大二、有复合发展想法、无明确辅修计划、性价比敏感、担心投入回报不成正比 
1. 基础信息：大一、大二为主，尚未确定未来发展路线，刷取大量辅修经验帖对比利弊； 
2. 行为特征：碎片化浏览辅修政策、各专业难度分享，纠结辅修vs双学位含金量，观望是否值得投入50学分； 
3. 心理特征：担心辅修拖累主修GPA、耽误保研/秋招，害怕零基础跟不上课程，希望低成本试错； 
4. 核心痛点：
- 看不懂繁杂的辅修培养方案，不清楚各专业学分、前置课程要求；
- 无法结合自身主修、兴趣、职业目标匹配适配辅修方向；
- 不清楚辅修对保研、留学、求职的实际加成； 
5. 匹配智能体功能：辅修方向智能测评、复合职业方向查询。 
典型用户故事：20岁中文大二学生，想走文转码路线，但不确定是否要辅修计算机，大量浏览小红书辅修避雷帖，担心50学分压力过大、编程零基础跟不上，希望工具评估自身适配度并提供轻量化自学路线。 

4.3 轻需求用户：仅需要跨专业自学资源，不参与官方辅修
用户标签：全年级覆盖、无辅修拿证需求、碎片化自学、追求轻量化跨学科学习 
1. 基础信息：不打算完成完整辅修学分，仅为提升求职竞争力补充交叉学科知识； 
2. 行为特征：四处搜集MOOC、自学笔记、学习路线，缺少系统性规划，自学容易半途而废； 
3. 心理特征：拒绝高额时间投入，不需要完整证书，只需要模块化、轻量化学习资源； 
4. 核心痛点：
- 跨专业自学资源分散，无统一知识体系与学习路径；
- 缺少学习进度跟踪、定时提醒，自学缺乏持续性； 
5. 匹配智能体功能：复合方向自学助手（附加功能）。 

4.4 沉睡/流失用户：暂无跨学科学习需求
用户标签：大一新生、专注本专业深造、无复合规划 
1. 基础信息：大一刚入学，仅熟悉本专业培养方案，未接触辅修、跨专业相关信息； 
2. 行为特征：仅偶尔浏览校园政策，不会主动检索跨学科内容； 
3. 心理特征：短期无跨专业诉求，认为辅修距离自身现阶段学习较远； 
4. 流失原因：产品功能与当下需求不匹配，缺少适配大一新生的专业分流、二次选拔指引； 
5. 优化方向：智能体新增大类分流、新生二次选拔政策查询模块，提前培育用户需求。

5.2 用户痛点问题
（1）辅修决策前痛点 
1. 政策信息分散晦涩：官方培养方案文件冗长，学生看不懂学分、报名、准出规则； 
2. 方向匹配无依据：不知道自身主修适配哪些复合赛道，无法预判辅修难度； 
3. 价值判断模糊：分不清辅修、双学位含金量差异，不清楚对保研、留学、求职的实际帮助； 
4. 南大特有门槛压力：50学分远高于国内多数高校，投入成本过高。
（2）课程规划与选课核心痛点
课表大规模时间冲突：主修、辅修课程时段重叠，调课程序复杂；
跨校区通勤成本高：辅修集中鼓楼开课，仙林学生往返消耗大量学习时间；
外系辅修课程名额少，抢课难度大；
无法结合个人作息（早八/集中上课偏好）优化四年整体学习安排。 
（3）跨专业学习门槛痛点 
1. 零基础跨专业缺少前置知识，课堂跟不上教学进度； 
2. 自学资源零散，无统一、可交互的知识学习树； 
3. 缺少学习监督、进度提醒，自学难以坚持。 
（4）复合发展就业痛点 
1. 招聘信息分散，难以筛选“XX专业+交叉背景优先”的实习、校招岗位； 
2. 缺少南大本校复合背景学长学姐求职案例、简历参考。
六、同类型智能体调查分析
（选取往届大赛校园规划智能体、跨学科学习助手以及市场上现有同类产品开展调研）
7.1 同类智能体功能与定位对比
7.1.1 往届火山杯相关智能体
1.  通用信息整合模型：将校园信息大量整合搜集，未能有针对性地给出具体的辅修政策、跨专业选课辅助决策，缺少实用性；
2.  通用跨学科学习AI：提供自学资源，但不绑定南大校内辅修制度、课程时间、校区通勤现实场景，无法解决学生选课、政策类专属痛点；
7.1.2 市场上主流学习助手类APP
1.  小猿搜题/猿辅导：核心定位为作业答疑与学科辅导，主打拍照搜题、错题整理、基础知识点讲解等功能，仅聚焦于单一学科的解题与基础学习，无校园政策适配、跨学科规划、就业衔接等功能，无法满足大学生辅修、复合成长的核心需求，且优质课程多为收费内容，智能化交互能力较弱，无法针对性解答校园规划类问题。
2.  洋葱学园：以校内同步课程、动画化知识点讲解为核心，新增AI精学模块可拆解错题逻辑、引导思考，但功能仍局限于学科知识学习，未结合高校校园场景，不了解南大辅修、多校区开课等特有制度，无法提供选课规划、跨校区通勤优化等专属服务，仅能满足基础自学需求，无法覆盖复合成长全流程。
3.  番茄ToDo/番茄土豆：核心为时间管理与专注力培养，主打任务清单、锁机、自习室、学习时长统计等功能，仅能辅助学生规划学习时间，无法提供学习内容推荐、校园政策解读、辅修规划、就业匹配等核心服务，与学生跨学科成长、复合求职的核心需求脱节，属于工具类APP而非智能规划助手。
7.2 本项目差异化创新机会总结
1.  南大校园深度专属：内置完整本校辅修培养方案、课程时间、校区分布、转专业政策，区别于通用智能体及市场上所有学习APP，精准适配南大校园场景，可实时解答学生专属政策疑问，解决政策信息不对称痛点；
2.  全链路一体化服务：打通兴趣测评、智能排课、自学陪伴、复合就业四大模块，覆盖学生跨学科成长全周期，实现“规划-学习-就业”一站式服务，形成完整服务闭环；
3.  冲突智能优化核心算法：针对南大课表冲突、跨校区通勤痛点，自动生成最优时间规划，是其他同类产品均不具备的独有功能，可切实解决学生校园规划中的实际难题，提升使用价值；
4.  分层适配不同用户：同时满足“拿证辅修学生”和“轻量化自学学生”两类人群需求，覆盖全部本科生，区别于番茄ToDo等无法适配大学生差异化需求的产品，兼顾实用性与灵活性，扩大用户覆盖范围；
5.  场景化智能交互优势：区别于小猿搜题智能化交互不足的短板，本项目将优化智能交互逻辑，可结合学生主修专业、兴趣爱好、职业目标，给出通俗易懂、针对性强的定制化方案，提升用户体验；
6.  免费化核心服务优势：核心功能（政策解读、辅修推荐、课表优化、就业检索）全部免费开放，区别于小猿搜题、猿辅导等优质功能收费的模式，降低学生使用门槛，提升产品普及率与用户粘性。

项目文档
福小禾 · 南大复合型人才成长助手
团队成员：管泽昊、仲嘉辉、叶颖、张佳怡
一、项目背景与用户痛点
1.1项目背景
当前新工科、新文科、交叉学科快速发展，市场对复合型人才需求持续扩张，南京大学大力推进跨学科、辅修培养制度，开设完整辅修专业体系。根据南大官方公开数据，全校本科在校生共15343人，校内开设本科课程3267门，选修课占比36.88%，具备充足跨专业学习基础；每年均有大量学生申请转专业，如2022年大一、大二分别有165人、57人获得转专业资格，电子信息、计算机、法学等复合热门方向申请人数最多，足以证明本科生跨专业、复合发展需求旺盛。
但通过小红书、微信平台学生真实分享、校内舆情调研发现：南大现行辅修制度存在学分高门槛、多校区通勤、课程冲突、信息分散等特有问题，学生在辅修决策、课程规划、跨学科自学、复合就业规划全流程存在大量共性痛点。现有通用学习工具、校园平台仅能单一查询政策，无法提供一站式个性化跨学科成长指导，因此本团队开发面向南大学生的复合型人才智能体，精准解决学生跨专业学习全流程难题。
1.2用户痛点
1.2.1辅修决策前痛点
(1) 政策信息分散晦涩
官方培养方案文件冗长，学生看不懂学分、报名、准出规则。
(2) 方向匹配无依据
不知道自身主修适配哪些复合赛道，无法预判辅修难度。
(3) 价值判断模糊
分不清辅修、双学位含金量差异，不清楚对保研、留学、求职的实际帮助。
(4) 南大特有门槛压力
所需学分高于国内多数高校，投入成本过高。
1.2.2课程规划与选课核心痛点
(1) 课表大规模时间冲突
主修、辅修课程时段重叠，调课程序复杂。
(2) 跨校区通勤成本高
辅修集中鼓楼开课，仙林学生往返消耗大量学习时间。
(3) 外系辅修课程名额少，抢课难度大
无法结合个人作息（早八/集中上课偏好）优化四年整体学习安排。
1.2.3跨专业学习门槛痛点
(1) 零基础跨专业缺少前置知识，课堂跟不上教学进度
直接进入辅修高阶课程时极易因听不懂而丧失学习信心。
(2) 自学资源零散，无统一、可交互的知识学习树
自学资源分散于各平台且无系统化的知识框架，学生难以把握学习路径，大量时间消耗在筛选而非吸收上。
(3) 缺少学习监督、进度提醒，自学难以坚持
辅修完全依赖自主时间管理，缺乏课程表式的进度约束，一旦遭遇主修学业高压期便容易陷入拖延直至放弃。
1.2.4复合发展就业痛点
(1) 招聘信息分散
难以筛选“XX专业+交叉背景优先”的实习、校招岗位。
(2) 缺少南大本校复合背景学长学姐求职案例、简历参考
学生难以评估复合方向的市场价值，也不知如何将交叉优势转化为简历上的有效表达。
二、产品概述与设计目标
2.1作品介绍
依托南京大学 “三三制” 本科培养模式，结合校内专属辅修政策打造的一站式复合型人才成长智能助手，覆盖新生方向探索、在校复合学习指导、求职就业引导全流程，解决本科生跨学科培养全链条痛点。
2.2作品目标
面向南京大学全体本科生，围绕交叉复合发展需求，通过自然语言交互，实现辅修政策答疑、辅修专业智能推荐、个性化课程规划、跨学科智能伴学、复合背景定向求职五大核心服务，全方位助力南大交叉复合型人才成长。
(1) 构建一站式跨学科政策信息平台，消除信息壁垒
梳理全校80余个全面开放辅修的专业目录及修读要求；解析“无需转专业即可转专业”的专业准入机制与两次集中调整机会。
(2) 建立专业课程体系知识图谱，智能体交互伴学，辅助在校与自学学习进程
构建覆盖全校各专业的课程体系数据库，以知识图谱形式呈现不同专业的核心课程、先修要求、学习难度与知识结构。整合DIY研读研究课程等开放性学习资源。
(3) 开发个性化复合方向智能推荐系统，匹配最优发展路径
基于学生的专业背景、兴趣偏好、能力特长与职业倾向，运用智能算法推荐适合的复合发展方向。
(4) 构建复合型人才就业画像与岗位匹配系统，衔接学业与职业
结合学生所学复合知识结构，推荐适配的实习机会与职业发展路径。
(5) 建立兴趣-能力-职业动态评估与反馈机制，实现持续优化
最终形成贯穿大学全程的自我评估工具，支持学生定期更新个人发展数据，系统动态调整推荐方案与发展建议，形成闭环成长机制。
三、用户需求分析与同类调研
3.1用户分层与画像构建
3.1.1核心高价值用户：有明确辅修计划的大二/大三本科生
(1) 用户标签
20-23岁、主修课业压力大、目标获取辅修证书、有明确复合就业或升学规划、高频查询政策与课表。
(2) 基础信息
大二、大三为主，覆盖商科、生命科学、中文、计算机等复合热门专业，是转专业落选后选择辅修的主力人群。
(3) 行为特征
反复查阅辅修学分要求、开课时间，手动对比主修与辅修课表，主动询问学长辅修难度、保研或出国含金量。
(4) 心理特征
愿意投入大量时间完成辅修，重视证书对求职、留学的加成，极度在意时间成本、课程冲突、跨校区通勤损耗。
(5) 核心痛点
南大辅修学分门槛远高于其他高校，课业负荷过重；
辅修课程部分在鼓楼校区，仙林主修生通勤单程40-60分钟，时间损耗巨大；
手动排课无法规避主修、辅修时间冲突，抢课名额少；
无法提前评估零基础跨专业辅修的学习难度。
(6) 匹配智能体功能
辅修智能推荐、个性化课程规划助手。
(7) 典型用户故事
21岁生科院大三本科生，计划辅修金融走生物医药行研赛道，多次在小红书发帖吐槽主修实验课与金融辅修课完全撞时间，跨校区通勤占用大量实习准备时间，不清楚自身基础能否跟上金融课程，希望工具自动生成无冲突四年课表并评估辅修难度。
3.1.2普通价值用户：观望型跨专业意向学生
(1) 用户标签
19-22岁、大一或大二、有复合发展想法、无明确辅修计划、性价比敏感、担心投入回报不成正比。
(2) 基础信息
大一、大二为主，尚未确定未来发展路线，刷取大量辅修经验帖对比利弊。
(3) 行为特征
碎片化浏览辅修政策、各专业难度分享，纠结辅修含金量，观望是否值得投入。
(4) 心理特征
担心辅修拖累主修绩点、耽误保研或秋招，害怕零基础跟不上课程，希望低成本试错。
(5) 核心痛点
看不懂繁杂的辅修培养方案，不清楚各专业学分、前置课程要求；
无法结合自身主修、兴趣、职业目标匹配适配辅修方向；
不清楚辅修对保研、留学、求职的实际加成。
(6) 匹配智能体功能
辅修方向智能测评、复合职业方向查询。
(7) 典型用户故事
20岁中文大二学生，想走文转码路线，但不确定是否要辅修计算机，大量浏览小红书辅修避雷帖，担心学分压力过大、编程零基础跟不上，希望工具评估自身适配度并提供轻量化自学路线。
3.1.3轻需求用户：仅需要跨专业自学资源，不参与官方辅修
(1) 用户标签
全年级覆盖、无辅修拿证需求、碎片化自学、追求轻量化跨学科学习。
(2) 基础信息
不打算完成完整辅修学分，仅为提升求职竞争力补充交叉学科知识。
(3) 行为特征
四处搜集MOOC、自学笔记、学习路线，缺少系统性规划，自学容易半途而废。
(4) 心理特征
拒绝高额时间投入，不需要完整证书，只需要模块化、轻量化学习资源。
(5) 核心痛点
跨专业自学资源分散，无统一知识体系与学习路径；
缺少学习进度跟踪、定时提醒，自学缺乏持续性。
3.1.4沉睡/流失用户：暂无跨学科学习需求
(1) 用户标签
大一新生、专注本专业深造、无复合规划。
(2) 基础信息
大一刚入学，仅熟悉本专业培养方案，未接触辅修、跨专业相关信息。
(3) 行为特征
仅偶尔浏览校园政策，不会主动检索跨学科内容。
(4) 心理特征
短期无跨专业诉求，认为辅修距离自身现阶段学习较远。
(5) 流失原因
产品功能与当下需求不匹配，缺少适配大一新生的专业分流、二次选拔指引。
(6) 优化方向
智能体新增大类分流、新生二次选拔政策查询模块，提前培育用户需求。
3.2分层用户需求对照表
3.3同类智能体调研
（选取往届大赛校园规划智能体、跨学科学习助手以及市场上现有同类产品开展调研）
3.3.1同类智能体功能与定位对比
(1) 往届火山杯相关智能体
通用信息整合模型：将校园信息大量整合搜集，未能有针对性地给出具体的辅修政策、跨专业选课辅助决策，缺少实用性；
通用跨学科学习AI：提供自学资源，但不绑定南大校内辅修制度、课程时间、校区通勤现实场景，无法解决学生选课、政策类专属痛点。
(2) 市场上主流学习助手类APP
小猿搜题/猿辅导：核心定位为作业答疑与学科辅导，主打拍照搜题、错题整理、基础知识点讲解等功能，仅聚焦于单一学科的解题与基础学习，无校园政策适配、跨学科规划、就业衔接等功能，无法满足大学生辅修、复合成长的核心需求，且优质课程多为收费内容，智能化交互能力较弱，无法针对性解答校园规划类问题。
洋葱学园：以校内同步课程、动画化知识点讲解为核心，新增AI精学模块可拆解错题逻辑、引导思考，但功能仍局限于学科知识学习，未结合高校校园场景，不了解南大辅修、多校区开课等特有制度，无法提供选课规划、跨校区通勤优化等专属服务，仅能满足基础自学需求，无法覆盖复合成长全流程。
番茄ToDo/番茄土豆：核心为时间管理与专注力培养，主打任务清单、锁机、自习室、学习时长统计等功能，仅能辅助学生规划学习时间，无法提供学习内容推荐、校园政策解读、辅修规划、就业匹配等核心服务，与学生跨学科成长、复合求职的核心需求脱节，属于工具类APP而非智能规划助手。
3.3.2本项目差异化创新机会总结
(1) 南大校园深度专属
内置完整本校辅修培养方案、课程时间、校区分布、转专业政策，区别于通用智能体及市场上所有学习APP，精准适配南大校园场景，可实时解答学生专属政策疑问，解决政策信息不对称痛点。
(2) 全链路一体化服务
打通兴趣测评、智能排课、自学陪伴、复合就业四大模块，覆盖学生跨学科成长全周期，实现“规划-学习-就业”一站式服务，形成完整服务闭环。
(3) 冲突智能优化核心算法
针对南大课表冲突、跨校区通勤痛点，自动生成最优时间规划，是其他同类产品均不具备的独有功能，可切实解决学生校园规划中的实际难题，提升使用价值。
(4) 分层适配不同用户
同时满足“拿证辅修学生”和“轻量化自学学生”两类人群需求，覆盖全部本科生，区别于番茄ToDo等无法适配大学生差异化需求的产品，兼顾实用性与灵活性，扩大用户覆盖范围。
(5) 场景化智能交互优势
区别于小猿搜题智能化交互不足的短板，本项目将优化智能交互逻辑，可结合学生主修专业、兴趣爱好、职业目标，给出通俗易懂、针对性强的定制化方案，提升用户体验。
(6) 免费化核心服务优势
核心功能（政策解读、辅修推荐、课表优化、就业检索）全部免费开放，区别于小猿搜题、猿辅导等优质功能收费的模式，降低学生使用门槛，提升产品普及率与用户粘性。
四、核心功能设计
4.1功能一：南大辅修政策答疑
4.1.1功能简介
自然语言交互，回答用户有关南大辅修政策的疑问。
4.1.2所需文件
辅修政策文件，包括各年份学生手册上的辅修说明，以及单独的辅修专业详细附件。
4.1.3重点问题
能够精确区分修读辅修课程的学分数所对应的能够获得的证明，如修30学分可得修读证明，修完要求课程可以得到辅修学士学位证书；
能够理解通过辅修实现跨专业转出的流程；
能够精确检索到某专业辅修所需学习的课程名、学分数、春/秋季学期等。
4.1.4重点交互
对话框、历史对话记录、政策原文查看按钮。

4.2功能二：辅修专业智能推荐
4.2.1功能简介
根据用户所提供的信息智能推荐可以选择辅修的方向，生成一份完整的辅修推荐报告（图片版）。
4.2.2所需文件
辅修专业详细附件、可靠的辅修推荐讲解以及人为编写的资料文档，如不同专业大一结束后所去的校区等。
4.2.3主要流程
步骤一
用户做出描述（应提醒要包括用户现在主修的专业、所在年级、兴趣倾向、能力特长、修读目标等）
步骤二
智能体根据描述追问一定问题补全信息，尽量推荐可行的辅修专业。
例如某些理科专业的辅修，若要取得最终学位，需要修读高层次的数学，而文科生一般并不修读高层次数学，因此推荐时应当询问是否会去修读高层次数学（修读可能使整体分数下降，失去在主修专业的竞争力），提醒若不修读，最多获得修读证明，无法得到最终辅修学士学位。
又例如某些专业后期所在校区不同，应询问是否接受后来不同校区通勤，或者是否具有申请免修不免考的能力，如果不接受不应推荐后期校区不同的专业（包括若后期主修专业在仙林校区，苏州校区这类基本通勤概率为零的应当直接排除）。
步骤三
生成一份南大辅修专业推荐报告，报告内容应包括推荐辅修专业名称、该专业课程体系展示、与主修专业课程重合度、总计学分数、专业的学科评估等级、推荐复合此专业原因等，以图片形式呈现。
4.2.4重点交互
初始基础信息填写（可以在打开软件一开始收集）、追问栏、报告生成键。

5.1应用场景与故事
5.1.1场景一：大一入学·政策咨询与辅修方向探索
(1) 适用阶段
大一上学期至大一下学期初。
(2) 场景故事描述
大一新生小林刚进入南京大学，就读于文学院汉语言文学专业。在新生入学教育中，她了解到南大实行“三三制”本科人才培养模式——即大类培养、专业培养、多元培养三个阶段，以及专业学术、交叉复合、就业创业三条发展路径。她对“交叉复合类”发展路径很感兴趣，但面对南大80余个全面开放的辅修专业，完全不知道从何入手。
小林打开福小禾，首先使用“南大辅修政策答疑”功能，输入：“我想了解一下南大的辅修政策，辅修和双学位有什么区别？”智能体根据南大辅修管理细则，准确回答：修满辅修专业培养方案规定的30个学分以上（含30），成绩合格但未达到学士学位要求者，可获得辅修专业结业证明；修完辅修专业培养方案规定的全部课程（各专业38-66学分不等，多在40-50之间），且完成辅修学位论文，可申请辅修学士学位，该学位在主修学士学位证书中予以注明，不单独发放。同时，智能体提醒她：辅修专业与主修专业的课程设置差异应达50%以上。
接着，小林使用“辅修专业智能推荐”功能。她按照系统提示填写了主修专业（汉语言文学）、所在年级（大一）、兴趣倾向（对传媒和商业感兴趣）、能力特长（写作能力强、逻辑思维较好）、修读目标（希望未来从事文化创意产业或传媒行业）。智能体根据这些信息，进一步追问了几个关键问题：
“您是否愿意修读高层次数学课程？部分管理学、经济学类辅修专业若要求取得辅修学士学位，可能需要修读高等数学，这可能影响您在主修专业的绩点竞争力。若不修读，最多只能获得辅修专业结业证明。”
“大二分流后，您的主修专业（汉语言文学）将在仙林校区就读。部分辅修专业所在院系后期可能在苏州校区，跨校区通勤基本不可行。您是否接受这一限制？”
小林回答了这些问题后，智能体生成了一份辅修专业推荐报告（以图片形式呈现），内容涵盖：推荐辅修专业名称、该专业课程体系展示、与主修专业课程重合度分析、总计学分数、专业的学科评估等级、推荐复合此专业的理由等。报告还附上了各专业大二后的校区信息，帮助小林提前规避跨校区问题。
小林最终锁定了“新闻学”作为辅修方向，并进入下一阶段。
5.1.2场景二：大二至大三·课程规划与复合学习陪伴
(1) 适用阶段
大一下学期选课至大三学年。
(2) 场景故事描述
小林确定辅修新闻学后，进入福小禾的“个性化课程规划”功能。系统已同步她主修专业（汉语言文学）的培养方案和辅修专业（新闻学）的培养方案。小林输入她的规划偏好：“我大一大二通修课和主修专业课比较多，希望辅修课程尽量安排在大三和大四。”智能体根据两套培养方案的课程学期分布，自动生成了一份个性化的辅修课程时间轴。
时间轴以交互式图表呈现，点击任意学年可查看该学年具体课程安排、课程学分和课程简介。系统还尽可能获取了主修专业课程的具体上课时间，自动筛选出与主修课程时间不冲突的辅修课程进行排布。对于部分冲突课程，系统提示小林可以关注学校的“免修不免考”政策，并提供了申请指引。
规划完成后，小林进入“复合方向伴学助手”的在校辅修模式。智能体结合汉语言文学和新闻学两专业的教材与知识体系，生成了一个个性化学习智能体。当小林在学习“新闻编辑”课程时遇到困难，智能体会用她熟悉的文学分析思维来类比解释新闻编辑的逻辑——“就像你在分析一部小说的叙事结构一样，新闻编辑也是在构建一个信息的叙事框架”——让跨学科知识更加融会贯通。
小林还开启了自学定时提醒和激励功能，智能体每周推送学习任务提醒，并显示辅修课程的学习进度条，帮助她在主辅双线学习中保持节奏。同时，独立自学模式为小林整合了小红书热门笔记及各网站知识资源，生成了一张“新闻学辅修知识树”，清晰展示从“新闻采写基础”到“数据新闻与可视化”不同阶段要掌握的知识技能。
5.1.3场景三：大四·职业方向探索与就业对接
(1) 适用阶段
大四求职季。
(2) 场景故事描述
到了大四，小林即将完成汉语言文学主修和新闻学辅修的全部课程。此时她打开福小禾的“职业方向探索开发”功能，希望找到能发挥她“文学+新闻”复合背景的岗位。
智能体自动检索了各大企业官网、求职公众号以及学校就业中心推送的招聘信息，筛选出明确标注“招聘A专业，有B专业背景者优先”的岗位推送给小林。例如，系统推送了一条招聘信息：
某文化传媒公司内容策划岗：要求中文、新闻传播相关专业优先，有跨学科背景（如文史哲+传媒）者优先考虑。
另一条推送来自金融行业：
某券商研究所消费行业研究实习生：要求985/211院校，中文、新闻或相关专业，具备优秀的文字表达能力和信息整合能力，有财经媒体实习经验者优先（复合背景优先）。
系统不仅推送岗位，还生成了参考简历模板，展示如何将“汉语言文学主修+新闻学辅修”的复合背景有效呈现在简历中——包括如何突出跨学科课程训练、辅修学位证明、以及相关的项目经历。同时，智能体提醒小林：辅修学士学位在主修学士学位证书中予以注明，面试时可以主动向HR说明这一复合培养背景。
小林通过福小禾的推送，成功投递了多家文化传媒和财经媒体的岗位，并获得了面试机会。在面试中，她能够清晰地向面试官阐述自己在“三三制”模式下选择的交叉复合路径——从大类培养到专业培养。

文档控制
摘要
本架构面向南京大学本科生的交叉复合成长全周期，覆盖政策答疑、辅修推荐、个性化课程规划、复合方向伴学与职业探索五项核心能力。系统将大模型限定在意图理解、信息归纳、解释生成与对话协作上；对学分、先修关系、时间冲突、校区通勤与推荐硬门槛采用结构化数据和确定性算法，以降低幻觉和不可复现风险。
架构采用 LangGraph StateGraph 作为运行时：根图负责路由、任务拆分、并行分发、状态合并、证据校验与人工介入；领域子图隔离上下文和工具权限。RAG 知识库承载受治理的校内政策、培养方案、课程知识与学习资料；独立 Search Agent 负责无专用 API 场景下的南大课程网页与招聘网页检索。MCP 统一工具发现与调用边界，Docker 沙箱隔离不可信代码、文档解析和浏览器执行。
适用性说明  本文给出可直接落地的逻辑架构、状态模型、服务拆分、接口契约、部署拓扑与验收指标；具体模型供应商、OCR 引擎和前端组件库可替换，不影响核心边界。

1 项目目标、需求范围与约束
1.1 需求归并
两份需求文档描述了同一产品的不同成熟度版本：完整项目文档提供用户痛点、画像、竞争分析、功能与用户旅程；“功能与应用场景部分”进一步明确五项功能所需材料、关键交互和典型故事。本设计将重复内容合并，并保留以下业务主线。
1.2 用户分层与连续旅程
核心辅修用户：需要政策核验、冲突排课、跨校区成本评估和完整学位路径。
观望意向用户：需要低成本试错、方向适配评估和投入回报解释。
轻量自学用户：不追求完整辅修证书，更关注模块化知识树、资源与持续学习。
暂无需求的新生：以大类分流、专业分流和早期方向探索为切入点，逐步沉淀画像。
系统应允许同一用户从大一的政策与方向探索，过渡到大二/大三的排课与伴学，再过渡到大四的职业检索；身份、偏好、已完成课程和关键决策需要跨会话保留，但敏感信息必须由用户可查看、可修改、可删除。
1.3 范围边界
MVP 包含  公开政策 RAG、辅修推荐、培养方案级课程规划、知识树与问答、公开岗位检索、来源引用、用户画像与历史会话、管理端数据摄取、MCP 工具层、隔离沙箱。
MVP 不承诺  不绕过南京大学统一身份认证、验证码或访问控制；不保证选课容量；不替代教务部门解释；不自动投递简历；不抓取违反站点条款或无法合法获取的公众号内容。需要登录的课表优先采用用户主动导出/上传，后续再建设授权连接器。
1.4 核心架构原则
证据优先：政策、课程与岗位事实必须关联来源、版本、抓取时间和可回溯快照。
确定性优先：学分、先修、时间冲突、校区通勤和硬门槛由规则引擎/约束求解器处理。
分层可信：治理后的 RAG 内容、临时网页证据、用户上传内容和模型生成内容采用不同信任级别。
最小权限：每个子图仅获得完成任务所需的 MCP 工具；写操作和外部副作用必须人工批准。
可恢复：图状态、工具调用和关键中间结果持久化，失败从最近检查点恢复，避免重复副作用。
先模块化单体、后按负载拆分：MVP 控制运维复杂度，Search、Sandbox 和 Worker 因安全/资源边界独立部署。

3.2 根状态、上下文与 Reducer
线程内可变数据放入 State；用户 ID、权限、模型配置、请求追踪等不可变数据放入 Runtime Context；跨线程偏好进入 Store。并行子图只写自己拥有的状态键，列表型证据通过 reducer 合并，防止并发覆盖。
from typing import Annotated, Literal
from typing_extensions import TypedDict
from langgraph.graph.message import add_messages

def merge_evidence(left: list, right: list) -> list:
    by_id = {item["evidence_id"]: item for item in [*left, *right]}
    return list(by_id.values())

class AssistantState(TypedDict, total=False):
    messages: Annotated[list, add_messages]
    intent: Literal["policy", "recommend", "schedule", "tutor", "career", "multi"]

    user_profile: dict
    evidence: Annotated[list[dict], merge_evidence]
    candidate_programs: list[dict]
    study_plan: dict
    answer: dict
    confidence: float
    warnings: list[str]
    pending_approval: dict | None

3.5 关键子图设计
3.5.1 政策答疑子图
流程：识别政策主题与适用年份 → 官方来源元数据过滤 → 混合检索 → 条款邻接扩展 → 答案生成 → 引用覆盖检查。政策结论不得仅依赖社区经验；未找到有效原文时明确拒答并给出查询入口。
3.5.2 辅修推荐子图
先收集主修、年级、兴趣、能力、职业目标、数学意愿、校区接受度、可投入学分与证书目标。随后进行硬过滤，再计算可解释评分。LLM 负责追问和解释，不负责修改硬门槛。

3.5.3 课程规划子图
以 CourseOffering、ProgramRequirement、Prerequisite、TimeSlot、CampusTravelTime 和用户偏好构造 CP-SAT 模型。硬约束包括先修、学分、开课学期、时间不重叠与不可行校区切换；软目标包括负载平衡、减少通勤、延后/提前偏好和方案鲁棒性。输出至少一个主方案与两个备选，并显示未知容量与课表时效。
3.5.4 伴学与职业子图
Tutor Agent 按当前课程节点从课程 RAG 和知识图谱检索，生成贴合主修思维的解释、诊断题和下一步任务；Career Agent 将课程、项目和技能映射到岗位要求，岗位事实来自 Search Agent，简历优化仅提供建议与可编辑模板，不自动投递。
4 独立 Search Agent 架构
4.1 为什么必须独立
项目缺少连接南大选课网站和主要求职网站的专用 API。网页检索具有高时效、易失败、登录态复杂、页面结构变化、合规约束和提示注入风险，不能被当成普通 RAG 工具隐藏在任意 Agent 内。因此 Search Agent 作为独立 LangGraph 子图和独立服务部署，向其他领域子图返回统一的 SearchEvidence，而不是直接给用户下结论。

4.4 Search 子图节点
search_intake：解析目标、时间范围、校区/岗位类型和允许来源。
query_plan：生成多组关键词、站点限定和同义专业名；限制最大来源数与成本。
source_policy：执行 robots、条款、域名、认证和抓取频率检查。
fan_out：通过 Send 并行调用课程、院系、企业、就业中心适配器。
browser_extract：在独立浏览器容器内导航、抽取、截图/快照和内容哈希。
normalize_dedupe：转换为 CourseOffering/JobPosting，按 URL、内容哈希和业务键去重。
evidence_grade：依据来源等级、发布时间、交叉验证和字段完整度打分。
search_finalize：只返回结构化证据；冲突事实并列返回，不让模型静默选择。
4.5 合规、安全与失败策略
禁止绕过验证码、付费墙、统一身份认证和技术访问控制；登录态检索必须由用户明确授权。
网页正文以 untrusted_content 进入状态，禁止将网页中的“系统提示”“调用工具”等文字当作指令。
浏览器只允许 http/https，阻断 file://、localhost、内网与云元数据地址，所有 DNS/HTTP 经出口代理。
单来源失败不阻断整体；已成功来源通过 Checkpointer 的 pending writes 保留。
课程缓存按学期与抓取时间失效，岗位缓存按小时级失效；TTL 配置化，答案始终显示 fetched_at。
若检索为空、来源冲突或新鲜度不足，返回“未查到/需核实”，不得根据常识补造课程或岗位。

5.1 知识域与可信分层
图 4  RAG 离线摄取与在线检索双通道
5.2 离线摄取管线
接入与落盘：上传/公开抓取后先写入 MinIO 原始区，记录 source_uri、etag、content_hash、fetched_at。
安全处理：病毒扫描、MIME/扩展名一致性检查、宏禁用；复杂解析进入无网络文档沙箱。
解析与保真：DOCX/PDF/HTML/OCR 统一为 Document AST，保留标题路径、页码、表格、脚注和附件关系。
结构化切分：政策按条款，培养方案按专业/模块/课程表，教材按章节；采用 parent-child chunk，子块 300-600 中文字，重叠 50-100 字。
元数据与实体：抽取学校/院系、专业、年级、学期、政策年份、课程码、校区、有效期和来源等级。
质量门禁：重复检测、低 OCR 置信度、缺页、表格解析失败和政策冲突进入人工审核队列。
索引发布：原文进 MinIO，结构化记录和全文索引进 PostgreSQL，向量进 pgvector，课程/先修/技能关系进 Neo4j。
版本切换：构建 staging 索引，通过黄金问题集后原子切换 active_version；旧版本保留回滚。
5.3 在线检索与上下文构建
检索不是一次向量相似度查询，而是“查询理解—元数据过滤—多路召回—融合重排—邻接扩展—证据组装”的流水线。政策问题优先使用 S/A 级与适用年份过滤；课程路径问题同时调用图检索；低召回或时效性问题通过 Command 转交 Search Agent。
query -> rewrite(0..3 variants)
      -> parallel[
           postgres_fts(top_k=30),
           pgvector_dense(top_k=30),
           neo4j_path(top_k=10)
         ]
      -> reciprocal_rank_fusion
      -> metadata/trust/freshness weighting
      -> cross_encoder_rerank(top_k=8)
      -> parent/neighbor expansion
      -> context_pack(token_budget, citation_map)
5.4 知识图谱
知识图谱用于表达向量检索不擅长的确定性关系，不作为单独的“炫技模块”。核心节点包括 Program、Course、KnowledgePoint、Skill、CareerPath、Policy；核心关系包括 REQUIRES、PREREQUISITE_OF、OFFERED_IN、LOCATED_AT、TEACHES、MAPS_TO_SKILL、MATCHES_CAREER。
课程规划：查询先修闭包和从当前已修课程到目标课程的可行路径。
知识树：从目标课程展开知识点依赖，生成阶段化学习路线。
职业映射：将课程与项目能力映射到岗位技能，不把专业名称作为唯一匹配依据。
图谱事实必须保存 source_id 和 valid_time；模型推断的边进入候选区，人工确认后发布。

6 MCP 工具架构
6.1 Host / Client / Server 关系
Agent Backend 是 MCP Host；内部 MCP Client Manager 为每个 MCP Server 维护独立连接、能力缓存、超时、认证与审计。近端受信服务使用 stdio，远端/独立部署服务使用 Streamable HTTP。MCP 只定义工具与上下文协议，不替代服务自身的业务鉴权。
6.2 工具契约示例
{
  "name": "search_course_offerings",
  "description": "检索公开或用户授权范围内的南大课程开设信息",
  "inputSchema": {
    "type": "object",
    "properties": {
      "course_names": {"type": "array", "items": {"type": "string"}},
      "term": {"type": "string"},
      "campus": {"type": ["string", "null"]},
      "allowed_domains": {"type": "array", "items": {"type": "string"}},
      "max_results": {"type": "integer", "minimum": 1, "maximum": 20}
    },
    "required": ["course_names", "term", "allowed_domains"]
  },
  "annotations": {"readOnlyHint": true, "openWorldHint": true}
}
所有工具输出统一包含 status、data、provenance、warnings、retryable、cost 和 trace_id。工具失败不得返回看似成功的自然语言；错误使用可机器判断的 code，例如 AUTH_REQUIRED、ROBOTS_DENIED、SOURCE_CHANGED、TIMEOUT、VALIDATION_ERROR。
对网页深度检索、批量索引和报告渲染等长任务，优先采用 MCP 2025-11-25 的 Tasks 能力暴露 working、input_required、completed、failed、cancelled 等状态；若所选 SDK 尚未完整实现，则由应用层 job_id 适配，保持同一状态机与取消语义。
6.3 MCP 安全与治理
Server Registry 使用允许列表和版本锁；工具列表变化需要兼容性检查，禁止模型连接任意用户提供的 MCP 地址。
Streamable HTTP 使用 OAuth/OIDC 短期令牌或服务身份，校验 token audience；禁止令牌透传给下游资源。
stdio Server 从进程环境获取最小必要凭据，日志中不输出密钥；远端服务建议 mTLS。
工具输入由 JSON Schema/Pydantic 双重校验；URL、文件路径、SQL/图查询采用参数化与范围限制。
只读工具可按策略自动调用；写、通知、导出敏感资料和高成本任务由 interrupt() 显示参数后审批。
每次调用记录 user_id、thread_id、run_id、tool、参数摘要、结果摘要、耗时、成本、权限决策和证据 ID。

10 核心业务流程
10.1 政策问答
Router 识别政策主题、目标年份/专业；缺失时 interrupt 追问。
Policy Agent 仅检索 S/A 级且适用时间匹配的文档，返回条款与定位。
Evidence Verifier 检查每个政策断言是否被引用支持；冲突版本并列展示。
前端展示摘要、置信度、适用范围与“查看原文”按钮。
10.2 辅修推荐
收集基础画像并识别缺失的硬条件（数学、校区、剩余学期、证书目标）。
规则引擎过滤不可行专业，评分器计算可解释得分；RAG 提供培养方案证据。
生成 Top-N、备选和明确不推荐项，显示学分、先修、校区、重合度和风险。
报告生成进入无网络沙箱，输出 DOCX/PDF/图片版产物；用户确认后保存。
10.3 个性化课程规划
读取培养方案与已修课程；Search Agent 尝试获取当前/未来开课证据。
对实时课表缺口给出 unknown，不用历史时间静默替代；用户可上传导出课表。
OR-Tools 生成主方案与备选，Plan Validator 复查学分、先修、时间和校区约束。
存在不可避免冲突时 interrupt 用户选择；恢复后只重跑受影响节点。
10.4 复合方向伴学
从目标课程/职业技能生成知识树，图谱给出先修路径，RAG 填充学习材料。
每次问答仅注入当前节点、相邻先修和用户主修背景摘要，控制上下文。
测验结果更新进度和掌握度；模型生成题经答案一致性校验后使用。
提醒属于外部副作用，首次创建必须 interrupt 审批并允许随时取消。
10.5 职业探索
将课程、项目与技能形成复合能力画像，不把辅修证书等同于岗位资格。
Search Agent 并行检索企业官网与学校就业中心，结构化岗位、截止时间与来源。
匹配器计算硬要求覆盖、技能相似度、复合背景偏好与地点/时间可行性。
Career Agent 解释匹配/差距，生成可编辑的简历表述；不自动投递。

14.2 核心验收用例
同一政策存在不同年份版本时，系统依据用户年级选中正确版本并展示适用范围。
文科学生拒绝高数且目标是辅修学位时，推荐结果必须过滤或显著标记相关硬风险。
仙林与苏州同日相邻时段课程不得进入可行课表；所有硬冲突为 0。

招聘页含提示注入文本时，不触发额外工具或泄露系统提示，只抽取岗位字段。
创建提醒或导出含个人信息的报告前触发 interrupt，拒绝后不产生副作用。
Search 一个来源超时后恢复运行，不重复抓取已完成来源，最终结果保留成功证据。

LangGraph 能力 | 项目中的具体用法 | 实施约束
StateGraph | 根图和五个领域子图采用显式节点/边，关键状态强类型化。 | 节点返回状态增量，不原地修改共享状态。
Command | 单域 goto、子图向父图 handoff、interrupt 恢复时 resume。 | 同一节点避免同时定义静态边与动态 goto。
Send | 多域问题、多个搜索源、多个候选专业与岗位并行 map-reduce。 | 使用 reducer；每个 Send 输入最小化。
Subgraph | 每个专家智能体独立子图；默认 per-invocation 并继承父图 checkpointer。 | 仅 Tutor 的连续学习状态可选 per-thread。
Checkpointer | PostgresSaver 按 thread_id 保存步骤状态、恢复失败与 HITL。 | 所有副作用节点幂等；记录 idempotency_key。

Streaming v2 | SSE 输出 messages、updates 与 custom 进度，前端展示节点状态。 | 不向用户暴露模型思维链和敏感内部状态。
RetryPolicy | 网络、MCP、模型短暂错误指数退避；源级失败局部降级。 | 参数错误、权限拒绝、校验失败不重试。

福小禾 · 南大复合型人才助手
项目介绍
以南大“三三制”本科培养模式背景，立足南大特色跨专业辅修政策，设计的一站式复合型人才成长助手，覆盖咨询推荐、过程伴学、就业探索等多方面
构思：
智能体可实现功能：
一、南大辅修政策答疑
功能简介：自然语言交互，回答用户有关南大辅修政策的疑问
所需文件：辅修政策文件，包括各年份学生手册上的辅修说明，以及单独的辅修专业详细附件
重点问题：
能够精确区分修读辅修课程的学分数所对应的能够获得的证明，如修30学分可得修读证明，修完要求课程可以得到辅修学士学位证书
能够理解通过辅修实现跨专业转出的流程
能够精确检索到某专业辅修所需学习的课程名、学分数、春/秋季学期等
重点交互：
对话框、历史对话记录、政策原文查看按钮
二、辅修专业智能推荐
功能简介：根据用户所提供的信息智能推荐可以选择辅修的方向，生成一份完整的辅修推荐报告（最好是图片版）
所需文件：辅修专业详细附件（如有可能再搜集一些可靠的辅修推荐讲解）以及一些为了信息精准人为编写的资料文档，如不同专业大一结束后所去的校区等。
主要流程：
Step 1: 用户做出描述（应提醒要包括用户现在主修的专业、所在年级、兴趣倾向、能力特长、修读目标等）
Step 2：智能体根据描述追问一定问题补全信息，尽量推荐可行的辅修专业。
例如某些理科专业的辅修，若要取得最终学位，需要修读高层次的数学，而文科生一般并不修读高层次数学，因此推荐时应当询问是否会去修读高层次数学（修读可能使整体分数下降，失去在主修专业的竞争力），提醒若不修读，最多获得修读证明，无法得到最终辅修学士学位
又例如某些专业后期所在校区不同，应询问是否接受后来不同校区通勤，或者是否具有申请免修不免考的能力，如果不接受不应推荐后期校区不同的专业（包括若后期主修专业在仙林校区，苏州校区这类基本通勤概率为零的应当直接排除）
Step 3：生成一份南大辅修专业推荐报告，报告内容应包括推荐辅修专业名称、该专业课程体系展示、与主修专业课程重合度、总计学分数、专业的学科评估等级、推荐复合此专业原因等，可以以图片形式呈现
重点交互：初始基础信息填写（可以在打开软件一开始收集）
追问栏、报告生成键
三、个性化课程规划
功能简介：根据用户选定的辅修专业，结合主修专业和辅修专业各学期的课程安排、用户年级，按照用户要求规划其个性化的课程辅修时间轴
所需文件：主修专业培养方案、辅修专业详细附件以及选课网站具体课程时间信息
重点问题：
时间轴可交互，能够点击后查看具体学年课程以及课程学分等简介；
应当按照用户的要求规划，例如希望大一大二时因为通修、专业课较多，希望少安排辅修专业的课程，则应当更多将辅修课程安排到后期
如果可能的话获取用户的主修专业课程具体上课的时间，自动筛选出在那一学年时间不冲突的辅修专业课程进行安排
重点交互：排课偏好、时间轴具体展开
四、复合方向伴学助手
功能简介：提供复合专业的学习资源与帮助激励
所需文件：能够搜集到的相应教材，小红书等网站内容
主要功能：
在校辅修模式：根据所选择的复合方向，结合主、辅修专业的教材，生成掌握主辅修专业知识的个性化智能体，提供更贴合主修专业思维的讲解
独立自学模式：结合小红书热门笔记以及各网站知识资源等，生成知识树，展示不同学习阶段要掌握的知识技能
可附加自学定时提醒、激励功能以及学习进度条等
重点交互：双模式切换，在校辅修模式中的智能体知识点讲解问答框，知识树，进度查看
五、职业方向探索开发
功能简介：搜集符合该复合方向的特定岗位，并给用户提供简历作为参考
所需文件：各大企业官网、求职公众号、学校就业中心推送的招聘信息
主要功能：
检索简历中的任职要求信息，筛选符合用户辅修方向的类似于“招聘A专业，有B专业背景者优先”的简历，推送给用户
例如商院职发就业助手大白文档里：
广发证券生物医药产业组实习生
要求：1.985/211或海外重点院校，要求生物医药相关专业或有创新药、医疗器械行研经验（金融复合背景优先考虑），大四保研或在读研究生（2026年12月后毕业）；2.熟练运用MSOffice，具备Wind、CEIC、Bloomberg等金融数据库使用经验者为佳；3.时间充裕，可尽快入职。
帮助优化简历，加入能突出复合优势的部分
主要交互：岗位搜索，每日岗位推送

应用场景：
场景一：大一入学·政策咨询与辅修方向探索
适用阶段：大一上学期至大一下学期初
场景描述：
大一新生小林刚进入南京大学，就读于文学院汉语言文学专业。在新生入学教育中，她了解到南大实行“三三制”本科人才培养模式——即大类培养、专业培养、多元培养三个阶段，以及专业学术、交叉复合、就业创业三条发展路径。她对“交叉复合类”发展路径很感兴趣，但面对南大80余个全面开放的辅修专业，完全不知道从何入手。
小林打开福小禾，首先使用“南大辅修政策答疑”功能，输入：“我想了解一下南大的辅修政策，辅修和双学位有什么区别？”智能体根据南大辅修管理细则，准确回答：修满辅修专业培养方案规定的30个学分以上（含30），成绩合格但未达到学士学位要求者，可获得辅修专业结业证明；修完辅修专业培养方案规定的全部课程（各专业38-66学分不等，多在40-50之间），且完成辅修学位论文，可申请辅修学士学位，该学位在主修学士学位证书中予以注明，不单独发放。同时，智能体提醒她：辅修专业与主修专业的课程设置差异应达50%以上。
接着，小林使用“辅修专业智能推荐”功能。她按照系统提示填写了主修专业（汉语言文学）、所在年级（大一）、兴趣倾向（对传媒和商业感兴趣）、能力特长（写作能力强、逻辑思维较好）、修读目标（希望未来从事文化创意产业或传媒行业）。智能体根据这些信息，进一步追问了几个关键问题：
“您是否愿意修读高层次数学课程？部分管理学、经济学类辅修专业若要求取得辅修学士学位，可能需要修读高等数学，这可能影响您在主修专业的绩点竞争力。若不修读，最多只能获得辅修专业结业证明。”
“大二分流后，您的主修专业（汉语言文学）将在仙林校区就读。部分辅修专业所在院系后期可能在苏州校区，跨校区通勤基本不可行。您是否接受这一限制？”
小林回答了这些问题后，智能体生成了一份辅修专业推荐报告（以图片形式呈现），内容涵盖：推荐辅修专业名称、该专业课程体系展示、与主修专业课程重合度分析、总计学分数、专业的学科评估等级、推荐复合此专业的理由等。报告还附上了各专业大二后的校区信息，帮助小林提前规避跨校区问题。
小林最终锁定了“新闻学”作为辅修方向，并进入下一阶段
场景二：大二至大三·课程规划与复合学习陪伴
适用阶段：大一下学期选课至大三学年
场景描述：
小林确定辅修新闻学后，进入福小禾的“个性化课程规划”功能。系统已同步她主修专业（汉语言文学）的培养方案和辅修专业（新闻学）的培养方案。小林输入她的规划偏好：“我大一大二通修课和主修专业课比较多，希望辅修课程尽量安排在大三和大四。”智能体根据两套培养方案的课程学期分布，自动生成了一份个性化的辅修课程时间轴。
时间轴以交互式图表呈现，点击任意学年可查看该学年具体课程安排、课程学分和课程简介。系统还尽可能获取了主修专业课程的具体上课时间，自动筛选出与主修课程时间不冲突的辅修课程进行排布。对于部分冲突课程，系统提示小林可以关注学校的“免修不免考”政策，并提供了申请指引。
规划完成后，小林进入“复合方向伴学助手”的在校辅修模式。智能体结合汉语言文学和新闻学两专业的教材与知识体系，生成了一个个性化学习智能体。当小林在学习“新闻编辑”课程时遇到困难，智能体会用她熟悉的文学分析思维来类比解释新闻编辑的逻辑——“就像你在分析一部小说的叙事结构一样，新闻编辑也是在构建一个信息的叙事框架”——让跨学科知识更加融会贯通。
小林还开启了自学定时提醒和激励功能，智能体每周推送学习任务提醒，并显示辅修课程的学习进度条，帮助她在主辅双线学习中保持节奏。同时，独立自学模式为小林整合了小红书热门笔记及各网站知识资源，生成了一张“新闻学辅修知识树”，清晰展示从“新闻采写基础”到“数据新闻与可视化”不同阶段要掌握的知识技能。
场景三：大四·职业方向探索与就业对接
适用阶段：大四求职季
场景描述：
到了大四，小林即将完成汉语言文学主修和新闻学辅修的全部课程。此时她打开福小禾的“职业方向探索开发”功能，希望找到能发挥她“文学+新闻”复合背景的岗位。
智能体自动检索了各大企业官网、求职公众号以及学校就业中心推送的招聘信息，筛选出明确标注“招聘A专业，有B专业背景者优先”的岗位推送给小林。例如，系统推送了一条招聘信息：
某文化传媒公司内容策划岗：要求中文、新闻传播相关专业优先，有跨学科背景（如文史哲+传媒）者优先考虑。
另一条推送来自金融行业：
某券商研究所消费行业研究实习生：要求985/211院校，中文、新闻或相关专业，具备优秀的文字表达能力和信息整合能力，有财经媒体实习经验者优先（复合背景优先）。
系统不仅推送岗位，还生成了参考简历模板，展示如何将“汉语言文学主修+新闻学辅修”的复合背景有效呈现在简历中——包括如何突出跨学科课程训练、辅修学位证明、以及相关的项目经历。同时，智能体提醒小林：辅修学士学位在主修学士学位证书中予以注明，面试时可以主动向HR说明这一复合培养背景。
小林通过福小禾的推送，成功投递了多家文化传媒和财经媒体的岗位，并获得了面试机会。在面试中，她能够清晰地向面试官阐述自己在“三三制”模式下选择的交叉复合路径——从大类培养到专业培养再到多元培养，以及辅修新闻学如何为她打开了新的职业视野。
