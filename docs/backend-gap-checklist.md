# 后端缺口清单

这份清单用于记录已完成前端页面中，暂时仍需要后端接口、数据库或真实业务流程支持的部分。每完成一个界面就追加对应条目，后续统一补齐并逐项验收。

## 绑定手机/邮箱

- [ ] 手机号“更换”：需要发送验证码、校验验证码并更新账号联系方式的接口。
- [ ] 邮箱“更换”：需要邮箱验证码校验和联系方式更新接口。
- [ ] “添加备用联系方式”：需要联系方式类型、验证状态和账号关联数据模型及接口。

## 个人主页

- [ ] 学习进度：当前使用前端占位数据 `28/50`，需要接入真实已修学分、培养方案总学分和完成度接口。
- [ ] 复合学习天数：当前使用前端占位数据 `120 天`，需要接入学习打卡或学习活动统计。
- [ ] 收藏岗位：当前读取浏览器本地存储，需要改为账号级收藏接口并支持跨设备同步。

## 花园首页

- [ ] 推荐卡片中的“已有 234 名种子同学加入该方向”：当前为前端固定展示，需要按辅修方向统计真实参与人数。
- [ ] 推荐卡片的方向热度、课程数量等信息：需要明确统计口径，并由后端随方向数据一起返回。

## 辅修推荐

- [ ] “你通过高等数学(A)了吗？”：当前只是跳转到编辑画像，画像接口没有记录具体课程通过情况，需要增加先修课程状态字段或课程记录接口。
- [ ] 推荐卡片中的种子人数与推荐解释：目前没有对应的方向参与统计和个性化解释持久化能力。

## 土壤条件画像

- [x] 当前已通过 `/profile` 接口读取和保存主修专业、兴趣方向和能力特长。
- [x] 主修专业已改为通过 `/programs` 接口从数据库专业目录加载。
- [ ] 兴趣和能力选项仍缺少统一字典、合法性校验及选项版本迁移。
- [ ] 画像修改后需要补充推荐结果失效标记、重新计算任务和推荐依据记录。
- [ ] 需要记录画像版本和更新时间，支持推荐结果追溯以及不同账号/设备间同步。
- [ ] 注册引导完成状态目前只保存在浏览器本地，需要账号级首次登录/画像完成标记，并由后端控制引导是否再次出现。

## 排课时间偏好

- [x] 当前已复用 `/profile` 接口，通过 `schedule_preferences` 字段读取和保存能量时段、上课时间段、课程集中度、午休习惯及晚间偏好标记。
- [ ] `schedule_preferences` 目前是自由 JSON，需要收敛为有版本的字段 schema，并增加枚举值校验、默认值和历史数据迁移。
- [ ] 时间偏好尚未接入真实排课计算，保存后只是进入冲突处理页面，需要结合课程时间、校区通勤和冲突策略生成可解释的课表方案。
- [ ] 需要补充排课方案的生成记录、采用状态和重新计算接口，支持用户修改偏好后重新生成推荐。

## 辅修冲突处理

- [x] 当前已复用 `/profile` 接口，通过 `schedule_preferences.conflict_strategies` 读取和保存用户选择的冲突处理策略。
- [ ] 冲突策略目前仍保存在自由 JSON 中，需要结构化字段、枚举值校验和策略优先级校验。
- [ ] 尚未根据真实课程时间、校区和教学方式识别冲突，也未执行免修、跨校区、线上课程或课程替换等策略。
- [ ] 保存后目前只进入推荐页面，需要补充冲突分析结果、排课方案生成和策略执行状态接口。

## 课程规划

- [x] 当前通过 `/programs` 和 `/programs/plan` 读取真实专业目录及结构化培养方案，前端按培养阶段和学期展示课程。
- [ ] 当前课程规划没有账号级的目标方案、已修状态、计划调整和采用状态，需要保存用户选中的培养方案版本及变更记录。
- [ ] 课程冲突提示和备选方案仍依赖现有培养方案返回结果，尚未结合真实课表、时间偏好、校区通勤和冲突策略动态计算。
- [ ] 前端导出目前只是浏览器生成文本日历，需要后端提供可追溯的导出任务、日历格式和与教务/系统日历同步能力。

## 漫步知识森林

- [ ] 当前知识树节点、节点状态和学习进度为前端展示数据，需要按账号和辅修方向返回知识点树、资源关联及完成状态。
- [ ] 点击知识点目前只展示前端说明，需要知识点资源列表、学习记录和完成状态更新接口。
- [ ] “在校辅修小径/独立自学小径”目前只切换前端视图，需要保存学习模式并分别生成课程/自学路线。
- [ ] 学习生长进度当前固定展示 `45%`，需要接入真实学习任务、课程完成度和阶段统计。
- [x] 伴学问答已有 `/chat` 流式接口，知识森林页保留了进入问答的入口。
- [ ] 从知识点进入问答时，目前只传递页面来源，尚未把具体知识点和关联资源上下文带入问答会话。

## 设置及其子页面

- ### 通知设置

  - [x] 当前已通过 `/preferences` 接口按账号读取和保存通知开关。
  - [ ] 将通知偏好从自由 JSON 收敛为有版本的字段 schema，并增加合法性校验和默认值迁移。
  - [ ] 接入真实通知发送服务，按学习计划、岗位、政策、推荐报告和课表事件触发消息。
  - [ ] 增加通知渠道管理、发送记录、失败重试和关闭后的生效边界。

- [ ] 学习提醒频次：当前选择项和保存按钮仍是前端占位，需要账号级提醒偏好、定时任务和通知投递记录。
- [ ] 岗位推送偏好：当前选择项和保存按钮仍是前端占位，需要保存岗位类型、城市、行业并供推送服务读取。
- [ ] 学习进度可见范围：当前选择项和开关未保存，需要隐私设置接口和访问权限校验。
- [ ] 数据同步：当前同步状态与操作是前端占位，需要同步任务、数据版本、失败重试和账号级备份接口。
- [ ] 清除缓存：当前按钮只完成页面展示，需要明确可清理数据范围并接入服务端缓存清理或状态刷新。
- [ ] 切换账号：当前账号列表为前端固定数据，需要账号列表接口、账号关联关系和账号状态返回。
- [ ] 切换会话：当前只是前端切换展示状态，需要切换会话/令牌、当前账号重新加载和权限隔离接口。
- [ ] 添加新账号：当前按钮没有实际流程，需要账号绑定、登录授权、重复账号校验和解除关联能力。

## 记录规则

- 前端页面可以先完成展示和交互占位，但不得把占位数据误认为真实业务数据。
- 后续后端阶段按页面逐项实现接口、持久化、权限校验和异常状态，再回填前端并验收。
