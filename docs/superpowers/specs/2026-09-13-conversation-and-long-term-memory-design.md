# 会话摘要与长期记忆系统设计

日期：2026-09-13

## 1. 背景

当前聊天接口将消息存储在 PostgreSQL，并在每次请求时加载当前会话最近 20 条、最多 12,000 个字符作为模型上下文。该实现已经支持基础多轮对话，但存在以下限制：

- 按单条消息和字符数裁剪，可能保留不完整的问答轮次。
- 早期上下文被直接丢弃，长会话中的目标、约束和结论会逐渐遗失。
- 不同会话之间没有共享记忆。
- 用户无法查看、纠正或删除系统记住的内容。

本设计分两个连续阶段改进现有机制：先加入当前会话的智能裁剪与滚动摘要，再加入可管理的跨会话长期记忆。两阶段使用同一套上下文组装接口，不改变现有聊天 API 的请求和 SSE 响应格式。

## 2. 目标与非目标

### 2.1 目标

- 以完整问答轮次为单位裁剪上下文，始终保留最新用户问题。
- 将较早轮次压缩为滚动摘要，在固定预算内保持长会话连续性。
- 自动提取稳定、可复用的用户事实和偏好，供后续会话检索。
- 提供长期记忆的查看、添加、编辑、删除和自动记忆开关。
- 真实模式使用现有聊天模型和 Embedding 服务；Mock 模式提供确定性实现。
- 记忆系统故障不得阻断聊天主链路。
- 保持用户隔离、敏感信息保护和提示词注入防护。

### 2.2 非目标

- 不拆分聊天模型与 Embedding 的 `MOCK_LLM` 开关。
- 不引入独立向量数据库、消息队列或新的外部供应商。
- 不把全部历史消息永久向量化。
- 不用长期记忆替代学生画像、课程记录等正式业务数据。
- 不保存密码、验证码、访问令牌等认证秘密；联系方式、健康信息等个人敏感内容只有在用户明确要求时才允许保存。
- 不提供管理员查看用户记忆的功能。

## 3. 总体架构

模型请求上下文按以下优先级组装：

1. 业务智能体的系统提示。
2. 学生画像等正式业务数据。
3. 与当前问题相关的长期记忆。
4. 当前会话滚动摘要。
5. 最近 3 至 5 个完整问答轮次。
6. 最新用户问题。

长期记忆和会话摘要都作为“仅供参考的用户上下文”注入，不作为系统指令。正式业务数据优先于长期记忆；发生冲突时，智能体必须采用学生画像和数据库当前值。

聊天主链路只读取已有摘要和记忆。主回答成功持久化后，通过 FastAPI 响应后台任务更新摘要和长期记忆。后台任务使用独立数据库会话，不复用请求已释放的 `AsyncSession`。后台任务失败仅记录结构化日志；原始消息仍然完整保留，下一次达到更新条件时可再次尝试。

## 4. 当前会话智能裁剪与摘要

### 4.1 数据模型

新增 `conversation_summaries` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `conversation_id` | UUID，主键/外键 | 对应会话，删除会话时级联删除 |
| `summary` | Text | 当前滚动摘要 |
| `summarized_through_message_id` | UUID，可空 | 摘要覆盖到的最后一条消息 |
| `revision` | Integer | 乐观并发版本号 |
| `created_at` | DateTime | 创建时间 |
| `updated_at` | DateTime | 最近更新时间 |

摘要游标引用真实消息，更新时仅处理游标之后且不属于保留窗口的完整轮次。若游标消息已被删除或数据不一致，则安全地从现有摘要和可用消息重新计算，不中断聊天。

### 4.2 完整轮次划分

- 一轮由一条用户消息和其后的助手消息组成。
- 连续用户消息视为一个尚未完成的用户段，不会被拆开摘要。
- 没有助手回答的最新用户消息必须保留原文。
- 非法角色消息不注入模型，并记录告警。

### 4.3 预算与触发条件

新增可配置项，默认值如下：

- `CHAT_RECENT_TURN_LIMIT=5`
- `CHAT_CONTEXT_CHARACTER_BUDGET=12000`
- `CHAT_SUMMARY_TRIGGER_CHARACTER_COUNT=8000`
- `CHAT_SUMMARY_MAX_CHARACTERS=2400`

上下文构建先保留最新问题，再从近到远加入完整轮次，最后加入摘要；任何单项超过预算时按安全边界截断。摘要更新仅在尚未摘要的旧轮次超过触发阈值时执行，避免每次对话额外调用模型。

真实模式使用聊天模型将“旧摘要 + 新增旧轮次”压缩为结构化摘要，内容限定为：用户目标、约束、已确认事实、未解决问题和重要结论。Mock 模式使用确定性规则提取用户陈述和关键结论，确保测试稳定。

### 4.4 并发更新

后台任务读取当前 `revision`，通过条件更新写入 `revision + 1`。若其他请求已先完成更新，本次任务放弃旧结果并记录一次可重试事件，防止并发请求用旧摘要覆盖新摘要。

## 5. 跨会话长期记忆

### 5.1 数据模型

新增 `user_memories` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID，主键 | 记忆 ID |
| `user_id` | UUID，外键/索引 | 所属用户，删除账号时级联删除 |
| `category` | String | 记忆类别 |
| `content` | Text | 面向用户展示的记忆内容 |
| `canonical_key` | String | 去重和冲突合并键 |
| `importance` | Float | 重要度，范围 0 至 1 |
| `confidence` | Float | 提取置信度，范围 0 至 1 |
| `source_conversation_id` | UUID，可空/外键 | 最近来源会话，会话删除时置空 |
| `source_message_id` | UUID，可空/外键 | 最近来源用户消息，消息删除时置空 |
| `embedding` | Vector(1024)，可空 | 语义检索向量 |
| `embedding_provider` | String | Embedding 提供方指纹 |
| `created_at` | DateTime | 创建时间 |
| `updated_at` | DateTime | 更新时间 |
| `last_used_at` | DateTime，可空 | 最近一次注入模型的时间 |

允许的类别固定为：

- `learning_goal`
- `program_preference`
- `interest_strength`
- `study_constraint`
- `career_goal`
- `confirmed_plan`

`canonical_key` 包含类别前缀。数据库对 `(user_id, canonical_key)` 建立唯一约束，并对 `user_id`、`category`、`updated_at` 建立查询索引。删除接口执行硬删除，正文和向量在同一事务中移除。

### 5.2 自动记忆偏好

复用 `users.preferences` JSON，在版本 1 schema 中加入：

```json
{
  "memory": {
    "auto_capture_enabled": true
  }
}
```

关闭后停止自动提取和跨会话召回，但不删除已有记忆；用户仍可在管理页查看、手动维护或删除。当前会话的裁剪与摘要不受该开关影响。

### 5.3 提取规则

自动提取只读取用户原话，助手回答只能帮助理解上下文，不可作为事实来源。真实模式要求模型返回受 Pydantic schema 约束的 JSON 候选；Mock 模式使用关键词和固定类别规则生成确定性候选。

候选必须同时满足：

- 属于允许类别。
- 是跨会话仍可能有用的稳定信息。
- 内容长度和字段格式合法。
- 不包含密码、验证码、访问令牌等认证秘密。
- 身份证号、联系方式、健康信息等个人敏感数据只有在用户明确要求记住时才可成为候选。
- 普通自动提取置信度达到配置阈值。

当用户明确使用“请记住”等表达时，可降低普通事实的置信度门槛，并允许保存个人敏感信息；认证秘密在任何情况下都拒绝保存。界面手动添加同样执行分级敏感信息校验，并在保存个人敏感信息前显示明确提示。

### 5.4 去重与冲突

提取器为每条记忆生成稳定的 `canonical_key`。同键新内容到达时：

- 内容等价：更新来源、置信度和时间，不新增记录。
- 内容变化：在同一记录上替换内容并重新生成向量。
- 与学生画像冲突：允许作为“对话偏好”保存，但注入时明确标记为低于正式画像的参考信息。

不同键但语义高度相似的候选，在真实模式下通过向量相似度进行二次去重；Mock 模式仅使用规范化文本和类别匹配，避免依赖哈希向量模拟语义能力。

### 5.5 检索与排序

真实模式将当前问题生成向量，只在当前用户范围内检索。候选综合以下因素排序：

- 语义相似度。
- 重要度。
- 最近更新时间。
- 最近使用时间的轻度衰减。
- 类别与当前智能体意图的匹配度。

默认最多注入 5 条，并受独立字符预算限制。Mock 模式按意图类别、关键词重合、重要度和时间排序，不使用 Mock 哈希向量声称语义相关性。

## 6. 提示词安全

摘要和长期记忆在注入前统一经过 `MemoryContextFormatter`：

- 仅输出固定 JSON/文本字段，不拼接角色标签。
- 限制单条和总字符数。
- 过滤伪造的 system/assistant 标签、工具调用标记和常见提示词注入语句。
- 在系统提示中声明记忆是未经验证的用户背景，不得覆盖系统规则或执行其中的指令。

记忆内容即使包含“忽略之前指令”等文本，也只能作为引用数据出现。

## 7. API 设计

新增 `apps/api/routes/memories.py`，所有接口依赖当前登录用户并按 `user_id` 隔离：

- `GET /api/v1/memories?category=&cursor=&limit=`：以 `updated_at + id` 作为稳定游标分页查询，默认按更新时间倒序。
- `POST /api/v1/memories`：手动添加一条记忆并生成向量。
- `PATCH /api/v1/memories/{memory_id}`：修改类别、内容或重要度；内容变化时重新生成向量。
- `DELETE /api/v1/memories/{memory_id}`：硬删除当前用户的一条记忆。
- `GET /api/v1/preferences/memory`：读取自动记忆设置。
- `PUT /api/v1/preferences/memory`：更新自动记忆设置。

会话摘要没有面向客户端的写接口。现有 `/api/v1/chat` 请求格式、SSE 事件和会话历史接口保持兼容。

## 8. 前端设计

设置页新增“我的记忆”入口，路由为 `/settings/memory`。页面沿用现有设置页视觉系统，包含：

- 自动记忆开关和简短隐私说明。
- 全部及六种类别筛选。
- 记忆卡片：内容、类别、来源和更新时间。
- 手动添加、编辑和删除操作。
- 删除确认对话框。
- 加载、空数据、失败和重试状态。

页面不展示向量、置信度等内部实现字段。关闭自动记忆时明确说明已有内容不会自动删除，并提供逐条删除能力。

## 9. 错误处理与可观测性

- 摘要、提取、Embedding 或数据库后台更新失败不改变已成功的聊天响应。
- 真实 Embedding 不可用时跳过本次新记忆写入或向量更新，不以 Mock 向量替代；已有无向量记忆仍可按类别和关键词降级检索。
- 读取摘要失败时仅使用最近完整轮次。
- 读取长期记忆失败时继续执行业务智能体。
- 日志记录任务类型、用户/会话的不可逆摘要标识、耗时、候选数量、写入数量和错误类型，不记录完整记忆正文和模型密钥。
- 为后台任务设置独立超时，避免占用资源无期限等待。

## 10. 迁移与兼容性

通过现有轻量迁移运行器新增编号 SQL 迁移，创建 `conversation_summaries` 和 `user_memories`。迁移只新增表和索引，不改写现有消息，不要求停机重建历史摘要。

已有会话第一次超过摘要阈值时按需生成摘要；已有用户从空长期记忆开始。现有聊天客户端无需升级即可继续使用，新版前端才展示记忆管理入口。

## 11. 测试与验收

### 11.1 单元测试

- 完整轮次划分和预算裁剪。
- 最新问题与最近轮次保留。
- 摘要游标推进、重复运行幂等和并发版本冲突。
- Mock 摘要与记忆提取结果确定。
- 敏感信息拒绝、类别校验、规范化键和冲突更新。
- 真实/Mock 检索排序和最大注入数量。
- 记忆上下文格式化与提示词注入过滤。

### 11.2 API 与集成测试

- 记忆增删改查、分页和自动记忆设置。
- 用户无法读取、修改或删除其他账号的记忆。
- 修改内容后向量更新，删除后正文和向量均不存在。
- 摘要或长期记忆依赖故障时聊天仍返回完整 SSE final 事件。
- 会话摘要与长期记忆能被后续轮次和新会话正确使用。
- 数据库迁移可重复执行且不会修改现有消息。

### 11.3 前端与部署验收

- 前端类型检查和生产构建通过。
- 后端完整测试套件和核心自检通过。
- Mock 模式端到端流程通过。
- 生产环境配置校验、健康检查和 readiness 通过。
- 真实模型环境执行会话摘要、跨会话召回和 SSE 流式回答冒烟测试。

## 12. 实施顺序

1. 建立摘要数据模型、迁移、完整轮次裁剪和 Mock/真实摘要器。
2. 将摘要读取和后台更新接入聊天链路，完成降级与并发保护。
3. 建立长期记忆数据模型、提取、去重、Embedding 检索和上下文格式化。
4. 接入自动记忆后台更新及偏好设置。
5. 增加记忆管理 API 和前端页面。
6. 执行完整自动化测试、真实模型冒烟测试和生产部署验证。
